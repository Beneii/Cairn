# Glossary

Key terminology and definitions for CAIRN.

## Core Concepts

### Agent

An AI model instance that performs specific work. Agents are constrained by the Orchestrator:
- Assigned specific tools they can use
- Limited to calling specific nodes
- Have memory tier restrictions
- Have execution time limits

Example: The `executor` agent can run tools; the `planner` agent creates task plans.

### Artifact

Output generated by an agent:
- Type: String identifier ("plan", "code", "analysis", etc.)
- Metadata: Type-specific data
- Origin node: Which agent created it
- Storage: Where to retrieve it

Example: When `coder` generates code, the code is an artifact.

### Execution Graph

The directed graph of nodes that defines how agents can communicate:
- Nodes represent agents
- Edges represent permissions (who can call whom)
- Hard-coded transitions (what can't happen is forbidden)

Based on LangGraph model.

### Job

A user request processed through the system:
- **Status:** queued | running | waiting | done | failed
- **Nodes traversed:** Path through execution graph
- **Artifacts:** Results generated
- **Costs:** Tokens and money spent

Example: "Write Python code" is a job that traverses multiple nodes.

### Node

A service or agent in the execution graph with specific:
- Allowed callers (permissions)
- Allowed tools (capabilities)
- Memory tiers (access levels)
- Max runtime (timeout)
- Assigned model (LLM)

Example: `executor` node can run tools; `planner` node creates plans.

### Policy

Rules that constrain system behavior:
- **SOUL.md:** Values, tone, purpose
- **IDENTITY.md:** Ownership, access
- **POLICY.md:** Hard safety rules
- **CAPABILITIES.md:** Tools and tier access

Policies are immutable at runtime.

## Architecture

### Cold Memory

Long-term storage with semantic search via vector embeddings.
- Indefinite storage
- RAG-based retrieval
- Read-only for agents
- Curator (Scheduler) promotes data here

### Curator

The Scheduler acting as a reviewer/promoter:
- Reviews warm memory
- Decides what to promote to cold
- Maintains quality of stored data
- Prevents pollution of knowledge base

### Executor

Service that runs tools safely:
- Sandboxed execution
- Secret redaction
- Structured outputs
- Audit trail

### Gateway

First contact point for user input:
- Intent classification
- Complexity estimation
- Immediate responses
- Job enqueueing

### Heartbeat

Periodic background task run by Scheduler:
- Every 30-60 minutes
- Scans for stalled tasks
- Performs incremental work
- Audits security
- Most heartbeats do nothing (correct)

### Hot Memory

Volatile, in-session storage:
- Current conversation
- Working context
- Temporary data
- Auto-expires after task completion

### Ledger

Append-only audit trail:
- Token counts
- Costs
- Tool calls
- Security events
- Hash-chained (tamper-evident)

### Memory Tiers

Three-level storage system:
- Hot: Volatile, current session
- Warm: Curated, persistent
- Cold: Long-term, RAG-based

### Nucleus

Physics-based animation showing system state:
- Idle: Gentle drift
- Thinking: Fast spin
- Tooling: Expansion with sub-agents
- Waiting: Frozen
- Error: Jitter

### Orchestrator

Graph execution engine:
- Enforces permissions
- Manages node transitions
- Controls tool allowlists
- Owns all permissions

### Scheduler

Background job runner:
- Runs heartbeat loop
- Executes scheduled jobs
- Curator for memory promotion
- Triggers periodic audits

### Warm Memory

Curated, semi-persistent storage:
- Task summaries
- User preferences
- Important events
- Stored as structured JSON + text

## UI Components

### Chat

Component displaying conversation:
- User messages
- Agent responses
- Collapsible tool outputs
- Timestamps

### Kanban

Four-column task visualization:
- Backlog: Not started
- Active: In progress
- Blocked: Waiting
- Done: Completed

### Logs

Real-time activity log:
- Tool calls
- State changes
- Errors
- Costs
- Type-based filtering

### Notes

Inbox system for agent messages:
- Read/unread states
- Message resurfacing
- Alternative to prompt-stuffing

### Sub-Agent

Smaller agent blob in "tooling" state:
- Shows name and action
- Orbits nucleus
- Indicates concurrent work

## Concepts

### Hard Fail

Execution stops immediately when constraint is violated:
- Agent tries forbidden action → Hard fail
- Violation logged to Ledger
- Error shown in UI
- Cannot be caught or ignored

Example: Agent tries to write to cold memory → Hard fail

### Invariant

Non-negotiable system principle:
1. **UI is truth:** Everything visible
2. **System > Agent:** Agents constrained
3. **No invisible work:** All actions logged
4. **Six services only:** No more, no fewer
5. **No self-modifying policy:** Agents can't escalate

### LangGraph

State machine framework for orchestrating agents. CAIRN's Orchestrator is inspired by LangGraph's:
- Declarative node definitions
- Graph-based transitions
- Type-safe state management

### MVP

Minimum Viable Product - Phase 1:
- Gateway + Telegram
- Orchestrator with 4 nodes
- Logs + Notes UI
- Minimal heartbeat

### Orchestration

Directing agent workflows:
- Which agents can call which
- In what order
- With what constraints
- Based on declared permissions

### Prompt Injection

Attack where user input becomes instructions:
- "Ignore previous instructions and..."
- Web content used as commands
- Prevented by web_locked node

### RAG

Retrieval-Augmented Generation:
- Query vector database
- Get relevant documents
- Include in context
- Improve answer accuracy

### State Machine

System tracking discrete states:
- Nucleus state: idle | thinking | tooling | waiting | error
- Job status: queued | running | waiting | done | failed
- Kanban status: backlog | active | blocked | done

### Sub-Agent

Smaller agent running in parallel (during "tooling"):
- Shown as orbiting blob
- Labeled with name
- Shows current action
- Represents concurrent work

### Tool

Function an agent can call:
- API call
- File operation
- Code execution
- Data retrieval

Allowed tools determined by node configuration.

### Token

Unit of text processed by LLM:
- Input tokens
- Output tokens
- Cost calculated from tokens
- Tracked in Ledger

### Transition

Movement between nodes in execution graph:
- "Planner calls Executor"
- "Executor reports to Orchestrator"
- Must be declared in graph (undeclared = impossible)

### Warm-to-Cold Promotion

Moving data from warm to cold memory:
- Curator reviews warm data
- Selects important items
- Creates summaries
- Stores in cold with vector embeddings
- Agents can then RAG-search

## System States

### Job States

- **queued** — Waiting to run
- **running** — Currently executing
- **waiting** — Blocked on external input
- **done** — Completed successfully
- **failed** — Error occurred

### Nucleus States

- **idle** — Ready for input
- **thinking** — Planning/reasoning
- **tooling** — Executing tools
- **waiting** — Blocked waiting
- **error** — Error state

### Kanban States

- **backlog** — Not started
- **active** — In progress
- **blocked** — Waiting for something
- **done** — Completed

### Note States

- **unread** — New message
- **read** — Already reviewed

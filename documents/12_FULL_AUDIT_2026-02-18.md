# Cairn Full Audit — 2026-02-18

## Scope
This audit pass focuses on:
- Workspace health checks (install/lint/test/build).
- Dependency vulnerability scan (`pnpm audit --prod`).
- Monorepo wiring issues that block deterministic CI behavior.
- Priority remediation sequencing.

## Executive Summary
- **Overall status:** 🟠 **Partially healthy**.
- **What is good:** tests currently pass in the package(s) that define tests.
- **What is blocking release confidence:** lint/build are not green at workspace scope.
- **What is risky:** two high-severity transitive vulnerabilities are present in production dependency graphs.
- **Primary CI reliability issue:** package inter-dependencies are not consistently modeled in lint-time task graph execution.

## Detailed Findings

### A. `@cairn/integrations` is not build/lint ready
**Impact:** breaks workspace lint/build and reduces confidence in release integrity.

**Observed evidence:**
- Workspace lint/build stop at `@cairn/integrations` with TS2307/TS2580/TS7006 class errors.
- `packages/integrations/package.json` lacks `@types/node` in dev dependencies despite Node APIs usage.
- `packages/integrations/tsconfig.json` enables `strict` mode; source currently contains implicit `any` callbacks.

**Risk level:** High (delivery blocking).

### B. Inter-package type/build coupling causes non-deterministic lint outcomes
**Impact:** lint may fail in consumers if producer workspace package artifacts (`dist`) are absent.

**Observed evidence:**
- `@cairn/tasks` fails lint when `@cairn/shared` has not been built first.
- Running `pnpm --filter @cairn/shared build` before `pnpm --filter @cairn/tasks lint` makes tasks lint pass.
- `turbo.json` does not model `lint` task dependencies (`dependsOn`) between workspace packages.

**Risk level:** Medium (CI instability / developer friction).

### C. Production vulnerability exposure remains open
**Impact:** transitive dependency exposure includes high-severity advisories.

**Observed evidence:**
- `pnpm audit --prod` returns non-zero with 2 high advisories and 2 low advisories.

**Risk level:** High (supply-chain/security posture).

### D. Warning-level packaging hygiene issue
**Impact:** install-time warnings and potential runtime/bin invocation confusion.

**Observed evidence:**
- `pnpm install` warns about failed `.bin/cairn-vault` creation because `packages/vault/dist/bin/cairn-vault.js` is not present at install time.

**Risk level:** Low/Medium (operational quality).

## Recommended Remediation Plan (Priority Order)

### P0 — Restore green lint/build
1. In `packages/integrations`:
   - add `@types/node` as dev dependency;
   - ensure tsconfig includes Node types where needed;
   - fix strict-mode implicit `any` sites in gmail/calendar parsers;
   - validate `googleapis` resolution with project references / module settings after type fixes.
2. Re-run `pnpm lint` and `pnpm build` at root.

### P1 — Make lint graph deterministic
1. Update `turbo.json` `lint` task to depend on upstream package build or lint artifacts where required (e.g., `"dependsOn": ["^build"]` or project-reference-aware lint strategy).
2. Prefer direct type exports or TS project references to avoid hard runtime dependency on built `dist` for pure typechecking.

### P1 — Close high vulnerabilities
1. Upgrade vulnerable transitive chains where feasible:
   - force patched `fast-xml-parser` version where ecosystem supports it;
   - patch/upgrade paths pulling vulnerable `tar`.
2. If immediate upgrade is blocked, document compensating controls and pin risk acceptance window.

### P2 — Remove install-time bin warnings
1. Ensure `@cairn/vault` bin target exists before linking, or adjust package `bin` strategy to avoid broken links prebuild.

## Audit Verdict
- Cairn is **not yet in a fully releasable monorepo state** due to lint/build blockers and unresolved high dependency advisories.
- The required fixes are tractable and mostly concentrated in integrations typing/dependency configuration and task-graph hygiene.

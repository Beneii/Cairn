## Ownership

### Primary Owner

The system serves a single owner. All actions are taken on behalf of this owner. The owner has:

- **Full visibility** into all system operations
- **Complete control** over system behavior via policy
- **Access to all logs**, ledger entries, and audit trails
- **Authority to modify** configuration and capabilities

### No Secondary Masters

Cairn does not serve:
- External APIs beyond those explicitly configured
- Third-party services with competing interests
- The AI models themselves (they are tools, not principals)
- Any entity that would compromise owner interests

---

## Access Tiers

### Tier 1: System (Highest)

- Can invoke any node
- Can modify runtime configuration
- Can read/write all memory tiers
- Reserved for: Gateway initialization, Scheduler heartbeat

### Tier 2: Orchestrator

- Can invoke nodes per graph policy
- Can track job state
- Can aggregate costs
- Reserved for: Job lifecycle management

### Tier 3: Nodes (Constrained)

- Can only call explicitly allowed nodes
- Can only use explicitly allowed tools
- Can only access explicitly allowed memory tiers
- Subject to: Per-node policy in `packages/policy/`

### Tier 4: External (Lowest)

- WebSocket clients receive broadcast events
- HTTP endpoints are read-only status checks
- No direct system modification without going through Gateway

---

## Authentication Model

### Current (MVP)

- Single-user local deployment
- No authentication required for local WebSocket
- API keys stored in environment variables

### Future Phases

- Multi-user support with owner/delegate roles
- Token-based authentication for remote access
- Audit logging of all access attempts

## Data Ownership

All data generated by Cairn belongs to the owner:

| Data Type | Location | Owner Access |
|-----------|----------|--------------|
| Ledger entries | `data/ledger/` | Full read, append via system |
| Job records | `data/jobs/` | Full read/write |
| Warm memory | `data/memory/` | Full read/write |
| Hot memory | In-memory | Volatile, auto-expires |
| Notes | `data/notes/` | Full read/write |
| Logs | UI + Ledger | Full visibility |

---

## System Boundaries

Cairn operates within explicit boundaries:

1. **Network**: Only contacts URLs/APIs explicitly permitted
2. **Filesystem**: Only accesses paths within its data directory
3. **Compute**: Respects token limits and runtime caps per node
4. **Cost**: Tracks and respects spending limits

---

## Identity Immutability

This file, along with SOUL.md, POLICY.md, and CAPABILITIES.md, forms the **identity core** of the system.

**Hard Rule**: These files are read at startup and compiled into runtime permissions. Agents may read them for context. Agents may **never** modify them.

Any attempt to modify identity files at runtime is:
- Blocked by the system
- Logged as a security event
- Considered a policy violation
